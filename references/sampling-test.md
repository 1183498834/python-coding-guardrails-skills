# 10 样本冒烟测试规范

**写完代码后立即进行 10 样本冒烟测试**：用真实数据快速验证代码正确性，**测试全部通过即结束并交付，不需要再运行一遍完整程序**。

完整程序（全量）运行只在以下两种情况下执行：
1. 10 样本测试发现问题，需要复现/排查时；
2. 使用者明确要求运行完整程序或全量数据时。

本文件规定抽样、运行、询问、报告四步。

## 1. 确定测试输入路径

1. 优先使用 argparse 中 `--input` / `--input-dir` 的 `default=` 值作为测试路径。
2. 检查该路径：**必须存在且包含可处理的数据**。
3. 以下情况视为"未指定有效路径"，**必须停下来询问使用者**，禁止自行编造路径或跳过测试：
   - 没有配置 `default=`（用户要求必填参数）；
   - 默认路径不存在、为空目录、或没有任何匹配的数据文件；
   - 用户明确说"用我自己的数据测试"但没给路径。

询问模板（在对话中向使用者提出，并给出可选建议）：

```
请指定用于测试的输入路径（目录或文件）：
1. 使用默认路径 <默认值>（若已配置且有效）
2. 指定其他路径：请提供目录位置
3. 若输入数据在命令行参数中传入，请直接给出运行命令
```

> 询问时必须等待使用者答复后再继续，得到路径后先做存在性与内容校验，再进入抽样。

## 2. 选取 10 个样本

- **候选多于 10 个**：均匀抽样，保证覆盖头、中、尾：

```python
import os
from pathlib import Path

def sample_10(paths):
    n = len(paths)
    if n <= 10:
        return paths
    idx = sorted({round(i * (n - 1) / 9) for i in range(10)})
    return [paths[i] for i in idx]
```

- **候选不足 10 个**：全部样本都跑，并向使用者说明"共 N 个，已全部运行"。
- **样本多样性优先**：若候选含不同类型（不同扩展名/不同大小/不同子目录），尽量每类都覆盖，而不是只挑前 10 个。
- 抽样可复现：涉及随机时固定 `random.seed(0)`。

## 3. 运行与断言

- 用与使用者相同的调用方式运行（如 `python script.py --input <测试路径> --output <临时输出目录>`）。
- 输出写入**临时测试目录**（如 `output_test_<时间戳>`），不要直接覆盖正式输出；测试通过后再让正式输出写入用户指定目录。
- 每个样本检查：
  - 进程退出码为 0；
  - 无未捕获异常（对应 `error-safety.md` 的异常规范）；
  - 输出文件已生成、非空、格式符合预期；
  - 抽样检查输出内容的合理性（尺寸、条数、字段完整）。
- 并发/批处理脚本测试时同样遵守 `concurrency.md` 与 `memory.md` 的资源约束。

## 4. 失败处理与结果报告

- **测试通过即结束流程**：10/10 通过 → 向使用者报告 → 交付。**禁止在测试通过后再运行一遍完整程序**（除非使用者明确要求全量运行）。
- 失败样本必须记录：**样本名 + 错误类型 + 错误信息**（前 3 条详细信息，其余汇总计数）。
- **修复 bug 后重新跑全部 10 个样本**，全部通过才算完成；不允许"只修一个跑一个"。
- 向使用者报告：

```
测试完成：10/10 通过
- 测试路径：<路径>
- 抽样方式：均匀抽样（共 N 个候选）
- 失败明细：无（若有，列出样本与原因）
```

- 若测试过程中发现需要使用者决策的问题（数据格式异常、参数含义不明确），先报告并询问，不擅自改逻辑。

## 5. 反例清单

| 反例 | 问题 |
| --- | --- |
| 先跑完整程序再测试 | 浪费大量时间，违背冒烟测试目的；应先 10 样本测试，通过即完成 |
| 无路径直接跑测试 | 编造路径或误用工作目录，结果不可信 |
| 默认路径为空仍继续 | 空跑"通过"产生假阳性 |
| 只测前 10 个文件 | 覆盖不到尾部/边界样本 |
| 测试输出覆盖正式输出 | 污染用户数据，违反 `error-safety.md` 原子写原则 |
| 失败后只修一个样本 | 其余 9 个可能仍坏，违反"全部通过才算完成" |
